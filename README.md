# Синтетические данные для кредитного скоринга

Сравнение лёгких методов борьбы с дисбалансом и CTGAN на задаче предсказания дефолта.
Гиперпараметры каждой модели подбираются заново на той выборке, на которой она учится.

Тема: применение GAN для борьбы с дисбалансом классов в табличных данных.
Исследовательский вопрос: как синтетическая генерация влияет на качество моделей кредитного скоринга.

## Почему три модели

Этого набора достаточно, чтобы отделить эффект генерации от эффекта самого классификатора.

| Модель | Зачем |
|---|---|
| Logistic Regression | Интерпретируемый линейный baseline |
| XGBoost | Основной бустинг для табличного скоринга, `scale_pos_weight` |
| CatBoost | Смешанные признаки German Credit, веса классов через `class_weights` |

LightGBM повторил бы роль XGBoost. Отдельная нейросеть как классификатор слабее на таблицах такого размера и смешала бы эффект CTGAN с эффектом архитектуры.

## Лестница методов

Замечание преподавателя учтено: GAN сравнивается не с «сырыми» данными, а с внутренней балансировкой библиотек и с более лёгкими генераторами.

1. `raw` — обучение без балансировки.
2. `class_weight` — baseline с внутренней балансировкой: веса классов в логистической регрессии, `scale_pos_weight` в XGBoost, `class_weights` в CatBoost. Множитель веса тоже подбирает Optuna.
3. `smote` — классический oversampling. На смешанных таблицах используется SMOTENC.
4. `borderline_smote` и `adasyn` — модификации SMOTE.
5. `noise` — копии дефолтов с гауссовским шумом по числовым признакам.
6. `gmm` — генерация числовых признаков смесью гауссиан; категории берутся у ближайшего реального дефолта.
7. `ctgan` — условная GAN для таблиц. Сеть учится только на дефолтах.

Oversampling и веса классов не смешиваются в одной конфигурации: иначе нельзя понять, что именно улучшило метрику.

Для генераторов Optuna сначала ищет гиперпараметры модели вместе с объёмом синтетики, затем лучшие параметры фиксируются и отдельно сравниваются четыре объёма из тезиса: +25%, +50%, +100% к числу дефолтов и полный баланс 1:1.

## Протокол, чтобы не было утечки

- Стратифицированный отложенный тест, 20%. В обучение и в генераторы он не попадает.
- Optuna максимизирует средний PR-AUC по стратифицированным фолдам обучающей части.
- SMOTE, ADASYN, шум, GMM и CTGAN применяются только внутри фолда.
- CTGAN обучается один раз на дефолтах фолда. Trial лишь выбирает, сколько строк взять из уже готового пула.
- Порог для F1 и Recall выбирается по out-of-fold предсказаниям train. На тесте порог не подстраивается.
- Итоговая модель заново учится на всём train с выбранным объёмом синтетики и один раз оценивается на тесте.

Основная метрика подбора — PR-AUC. Рядом считаются ROC-AUC, F1, Recall и Precision по классу дефолта.

## Данные

| Датасет | Что запускается по умолчанию |
|---|---|
| German Credit, OpenML `credit-g` | Все 1000 строк, около 30% плохих кредитов |
| Give Me Some Credit | Стратифицированные 8000 строк из 150000. Полный файл: `--giveme-rows 0` |
| Home Credit Default Risk | Тот же код, если положить `data/home_credit/application_train.csv` и добавить `--datasets home` |

Полные Give Me Some Credit и Home Credit вместе с Optuna и CTGAN на трёх моделях считаются много часов. Подвыборка сохраняет долю дефолтов и позволяет честно сравнить методы. Ограничение прямо указано в отчёте и на слайдах.

## Запуск

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
# macOS: XGBoost и CTGAN оба используют OpenMP. Флаг уже выставляется в run_experiment.py.
brew install libomp
.venv/bin/python run_experiment.py --trials 12 --cv 3 --ctgan-epochs 300 --giveme-rows 8000
```

Опубликованный прогон: German Credit целиком и стратифицированные 8000 строк Give Me Some Credit, 12 испытаний Optuna, 3 фолда, CTGAN на 300 эпох. Home Credit в цифры не входил.

На German лучший тестовый PR-AUC у CatBoost + смесь гауссиан, объём +25% (0.708). На Give Me Some Credit лучший PR-AUC у CatBoost + шум, объём +50% (0.373). CTGAN эти конфигурации не обогнал. Для логистической регрессии на сильном дисбалансе решающими оказались веса классов, а не генератор.

Полезные флаги:

```bash
.venv/bin/python run_experiment.py --datasets german --models xgboost --methods class_weight smote ctgan
```

Уже посчитанные пары «датасет × модель × метод» пропускаются. Чтобы пересчитать всё с нуля, удалите `results/metrics.csv` и `results/optuna.db`.

Результаты:

- `results/metrics.csv` — тест и выбранный объём синтетики
- `results/level_sweep.csv` — PR-AUC четырёх объёмов
- `results/synth_quality.csv` — Вассерштейн, KS, разрыв корреляций, JS по категориям
- `results/summary.md`, `results/pr_auc.png`, `results/recall.png`
- `presentation.pptx` — 5 слайдов по этому прогону

Качество синтетики считается на обучающей части при балансе 1:1. Это диагноз генератора, а не тестовая метрика классификатора.
